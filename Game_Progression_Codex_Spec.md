# Игра с растущей битой — рабочая спецификация для Codex

> **Статус:** согласованные правила и поэтапный план реализации; нерешённые детали перечислены в разделе 6.
> **Назначение:** рабочий документ для реализации механики в существующей архитектуре игры. При реализации дополнять его принятыми решениями и отмечать завершённые этапы.
> **Область:** баунды, последовательность паттернов, появление шариков и повтор с баунда перед самым дальним достигнутым. Это не полное ТЗ на управление, физику и эффекты.

## 1. Принцип игры

Игрок поднимается вместе с растущей битой, удерживает баланс и взаимодействует с шариками. Стартовая точка — в центре поля, под основанием биты. Очки равны высоте в метрах. Если баланс потерян, бита падает; после визуального возврата игрок начинает заново с **начала баунда, предшествующего самому дальнему достигнутому баунду**.

Путь состоит из высотных участков — **баундов**. Каждый баунд задаёт количество паттернов, которым достаются равные доли его высоты. При `PatternCount = 0` баунд пустой: рост и его множитель скорости действуют, шарики не появляются. Паттерны выбираются из **одной заранее заданной последовательности для всей игры**. Переход к следующему баунду не сбрасывает эту последовательность.

## 2. Термины и данные

| Сущность | Содержимое | Правило |
| --- | --- | --- |
| `GameProgressionAsset` | Упорядоченный список ссылок на отдельные ассеты баундов; глобальная последовательность ID паттернов; каталог паттернов 1–9 | Единственный источник порядка прохождения. |
| `BoundAsset` | Название, `HeightFrom`, `HeightTo` в метрах, `PatternCount`, множитель скорости роста | Самостоятельный ассет; не хранит список паттернов или доли отдельных паттернов. |
| `PatternAsset` | Уникальный `PatternId` от 1 до 9; ровно 9 событий появления; ровно 9 радиальных координат | Ассет может встречаться в последовательности многократно. |
| Событие появления | `LocalHeight` от 0 до 1; вид шарика | Девять событий идут по порядку высоты. `LocalHeight` отсчитывается **внутри равной доли баунда**, выделенной текущему паттерну. |
| Радиальная координата | Угол и расстояние от центра | Координата с индексом `i` соответствует событию с индексом `i`; источник координат выбирается отдельно. |

`PatternSequence` хранится в `GameProgressionAsset` как строка цифр π. При чтении нули пропускаются, а первые `sum(Bounds[*].PatternCount)` ненулевых цифр преобразуются в ID 1–9. Остальные цифры строки остаются запасом для будущих баундов. Повторяющиеся ID допустимы; каждому ID соответствует один ассет каталога. Строка может быть длиннее текущей потребности, но после пропуска нулей должна содержать достаточно цифр. Конечная строка автоматически не зацикливается; при расширении баундов её можно продолжить, не меняя префикс. Символы, кроме цифр, недопустимы.

### Виды шариков

| Вид | Смысл | В обычном паттерне |
| --- | --- | --- |
| Красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый | Семь отдельных одноцветных валютных шариков | Да |
| Чёрный с логотипом | Дебафф: среди идей заморозка, взрыв, ветер, вызов препятствия | Да |
| Белый с логотипом | Бафф: среди идей ускорение роста, ограничение падения, стабилизация | Да |
| Серый с вопросом | Бафф **или** дебафф | Да |
| Золотой | Бонус с наградой за раскрытие скрытой загадки | **Нет**; отдельная будущая механика |

Всего задумано 11 видов, из них 10 доступны обычным паттернам. В каждом вхождении паттерна появляется **ровно 9 шариков**. Один шарик имеет один конкретный цвет: радужный многоцветный шарик не предусмотрен. Повторы вида внутри девяти событий допустимы, включая девять одинаковых шариков. Каждый цветной шарик даёт 1 единицу валюты. Белый шарик выбирает случайный доступный бафф (сейчас Boost или TiltProtection), чёрный — случайный доступный дебафф. Серый шарик выбирает бафф или дебафф с вероятностью 50/50, затем случайный доступный эффект выбранного типа. Золотой шарик и его награды будут отдельной будущей механикой.

## 3. Порядок проигрывания

Для баунда с индексом `b` (с нуля):

```text
sequenceStart(b) = sum(Bounds[k].PatternCount for k = 0 .. b-1)
patternId(b, p) = PatternSequence[sequenceStart(b) + p]
```

Здесь `p` — номер паттерна внутри непустого баунда, от `0` до `PatternCount - 1`. Например, если баунд 1 содержит 3 паттерна, а баунд 2 — 4, первый берёт позиции последовательности `0..2`, второй — `3..6`. Пустой баунд не расходует цифры последовательности; следующий непустой баунд продолжает её с того же места. Сохранение баунда не требует отдельного сохраняемого индекса последовательности: он вычисляется из предыдущих `PatternCount`.

### Высота события

Для непустого баунда при `n = Bound.PatternCount > 0`, индексе паттерна `p` и локальной высоте события `t`:

```text
spawnT      = (p + t) / n
spawnHeight = Bound.HeightFrom +
              (Bound.HeightTo - Bound.HeightFrom) * spawnT
```

Таким образом каждый паттерн занимает `1/n` высотного диапазона баунда. **Пример:** баунд `1000–2000 м`, четыре паттерна. Второй паттерн занимает `1250–1500 м`; его событие с `t = 0,6` происходит на `1400 м`. Баунд «Стратосфера: 15 000–50 000 м» — пример возможных границ, а не фиксированное значение для проекта.

### Из какого паттерна брать координаты

У текущего паттерна берутся **виды и локальные высоты девяти событий**. Координаты берутся из **предыдущего элемента глобальной последовательности**, даже при переходе между баундами.

```text
globalIndex = sequenceStart(b) + p
currentId = PatternSequence[globalIndex]
current   = PatternCatalog[currentId]

if globalIndex == 0:
    coordinateSourceId = (current.PatternId == 1) ? 9 : current.PatternId - 1
    coordinateSource = PatternCatalog[coordinateSourceId]
else:
    coordinateSourceId = PatternSequence[globalIndex - 1]
    coordinateSource = PatternCatalog[coordinateSourceId]

for i in 0..8:
    kind, t       = current.SpawnEvents[i]
    angle, radius = coordinateSource.Coordinates[i]
```

Исключение `ID − 1` (с переходом `1 → 9`) действует **только для первого элемента всей последовательности**. Оно не применяется к первым паттернам следующих баундов.

**Пример:** для глобальной цепочки `3 → 1 → 4 → 1` источники координат соответственно `2 → 3 → 1 → 4`. Если баунд заканчивается на `4`, а следующий начинается с `1`, координаты первого паттерна нового баунда берутся у `4`.

## 4. Падение и повторный проход

При входе в баунд сохраняется самый дальний достигнутый баунд. При проигрыше игровое прохождение возобновляется **с начала предыдущего баунда**: если игрок вошёл в 5-й баунд, стартует 4-й; если вошёл в 6-й, стартует 5-й. Для первого баунда точка повтора — начало первого баунда. Все шарики и события повторяемого баунда появляются снова, в том числе уже собранные в предыдущей попытке. Источником координат для его первого паттерна остаётся предшествующий элемент **глобальной** последовательности, а не последний сыгранный перед падением шарик/паттерн.

Перед повтором показывается быстрый **визуальный рост от нулевой высоты до `HeightFrom` баунда повтора**. Во время него управление, спавн и остальные игровые события отключены. По окончании начинается игровой проход с первого паттерна и первого события выбранного баунда. Высота/очки сбрасываются и восстанавливаются до стартовой высоты; валюта накапливается и сохраняется между попытками и запусками приложения. Слоты баффов и активные эффекты при падении очищаются.

Сохранять нужно как минимум индекс самого дальнего достигнутого баунда и накопленную валюту. Индекс паттерна вычисляется из `PatternCount` предшествующих баундов, а не сохраняется отдельно.

## 5. Проверки данных и проверочные примеры

Проверять при редактировании данных или запуске:

- `HeightTo > HeightFrom`, единица измерения едина для всех баундов, `PatternCount >= 0`, множитель скорости роста положителен. `HeightTo` предыдущего баунда равен `HeightFrom` следующего.
- Сумма всех `PatternCount` не превышает длину заранее заданной последовательности.
- Все ID последовательности принадлежат `1..9`; в каталоге есть по одному ассету на каждый ID.
- Каждый паттерн содержит ровно девять событий и девять координат; `LocalHeight` лежит в `[0,1]` и идёт по неубыванию.
- Золотой шар не допускается в событиях обычного паттерна. Начальный радиальный диапазон паттернов — `0,22–0,33` от центра, как в overrides `BalloonManager` основной сцены. Поля координат ограничены в Inspector и повторно приводятся к допустимому диапазону в `OnValidate`.

Минимальные сценарии для проверки реализации:

1. `PatternCount = 4`, высота `1000–2000 м`, второе вхождение, `LocalHeight = 0,6` → `1400 м`.
2. Цепочка `3 → 1 → 4 → 1`: источники координат `2 → 3 → 1 → 4`.
3. Граница баундов после `4`: следующий `1` использует координаты `4`, а не `9`.
4. Повтор номера паттерна в списке не удаляет вхождение и не меняет выбор предыдущего элемента.
5. Вход в баунд 5 сохраняет его как самый дальний достигнутый; падение запускает игровой проход баунда 4 с начала и заново создаёт его шарики после завершения визуального роста.
6. Вход в баунд 6 переносит следующую точку повтора на начало баунда 5.
7. Во время визуального роста до точки повтора нет управления, шариков и игровых событий; валюта при падении и перезапуске приложения не уменьшается, баффы и активные эффекты очищаются. При запуске приложения высота остаётся нулевой, пока игрок не разблокирует старт горизонтальным положением телефона. Только после этого начинается визуальный рост.
8. Баунд с `PatternCount = 0` не создаёт шариков и не расходует цифры последовательности, но рост продолжается с его множителем скорости. Первый паттерн после пустого баунда использует предыдущий глобальный паттерн как источник координат.

## 6. Отложенные и технические вопросы

1. Управление битой и критерий потери баланса сохраняют действующие правила проекта; изменения физики шариков и роста вне описанного расписания согласовываются отдельно.
2. Скрытые загадки, отдельный спавн золотого шарика, его награды и трата валюты — будущие механики.
3. Конкретные диапазоны высот, названия и множители скорости каждого баунда заполняются в отдельных ассетах. Конкретные девять событий и координат каждого паттерна также заполняются в ассетах.
4. При реализации определить техническое правило для одновременных событий на одной высоте или границе долей: каждое событие должно сработать ровно один раз в заданном порядке.
5. Если для белого, чёрного или выбранной стороны серого шарика нет доступного эффекта, шарик пропускается с ошибкой в Console. Эффект противоположного типа не подставляется.
6. После достижения `HeightTo` последнего настроенного баунда начинается вычисляемый бесконечный пустой баунд. Его номер всегда на единицу больше количества настроенных баундов, начало равно `HeightTo` последнего, паттернов нет, множитель роста берётся из последнего настроенного баунда. Он сохраняется как достигнутый баунд; повтор начинается с начала последнего настроенного баунда. Отдельный ассет для бесконечного баунда не создаётся. При добавлении новых настроенных баундов бесконечный автоматически сдвигается за ними.

## 7. Инструкция для Codex в игровом репозитории

Следуй утверждённым правилам разделов 1–5 и плану раздела 8. Перед каждым этапом проверяй актуальные связи в сцене и префабах, после этапа отмечай результат проверки в этом документе. Технические вопросы раздела 6 не решай молча, если выбор изменит игровое поведение. Не создавай золотой шар внутри обычных паттернов и не меняй правило координат при повторе баунда.

## 8. Поэтапный план реализации

Статусы этапов обновлять по мере работы; перед отметкой «готово» выполнять указанную проверку. Первый этап реализован как структура данных; заполнение конкретных ассетов баундов и проверка их числовых диапазонов запланированы на этап 10.

1. **[x] Данные баундов.** Созданы типы `BoundAsset` с названием, `HeightFrom`, `HeightTo`, `PatternCount` и множителем скорости, а также `GameProgressionAsset` с упорядоченным списком ссылок на отдельные ассеты баундов. `PatternCount = 0` допускает пустой баунд. Создан `GameProgression.asset`. **Проверено:** поля сериализуются как данные отдельных `ScriptableObject`; старая конфигурация и её связи не изменены. Конкретные экземпляры, порядок и стыковка диапазонов проверяются при наполнении на этапе 10.
2. **[x] Данные паттернов.** `PatternAsset` хранит ID 1–9, девять событий (`LocalHeight`, вид шарика) и девять радиальных координат (угол, расстояние). Обычные события допускают десять видов без золотого; повторы видов разрешены. `OnValidate` удерживает размер обоих массивов равным девяти и ограничивает угол и радиус; начальный диапазон радиуса `0,22–0,33` взят из основной сцены. Тестовый `Pattern 1` заполнен девятью событиями: семь цветов радуги, затем красный и оранжевый, высоты `0,1–0,9`, случайные координаты в допустимом диапазоне. **Проверено:** событие `i` соответствует координате `i`; проверка неубывания высот добавлена на этапе 3.
3. **[x] Последовательность и валидация данных.** `GameProgressionAsset` хранит строку цифр и каталог ассетов 1–9. Баунды задают количество используемых ненулевых цифр; при загрузке и изменении данных эта часть строки преобразуется в кешированный массив ID. Проверяются символы строки, достаточная длина после пропуска нулей, каталог, границы баундов, число и порядок событий, виды шариков и координаты. `TryValidate` доступен для проверки перед игровым запуском. **Текущее наполнение:** все девять ассетов паттернов созданы и внесены в каталог. У `Pattern 2`–`Pattern 9` предварительные цвета и координаты. Временно во всех паттернах чёрные события заменены красными, серые — зелёными; поддержка этих видов в коде сохранена. Строка содержит 30 первых цифр π без десятичной точки: `314159265358979323846264338327`. Три текущих баунда задают `PatternCount = 0, 2, 3` и используют первые пять ID: `3, 1, 4, 1, 5`. При добавлении баундов оставшаяся часть строки будет использоваться по порядку.
4. **[ ] Расписание событий и проверка в Play Mode.** Код реализован: `PatternEventSchedule` вычисляет глобальный индекс паттерна, долю баунда, высоты событий и источник координат. `PatternEventScheduler` на `GameManager.prefab` читает высоту из `ScoreCounter`, публикует событие при пересечении порога и пишет его в Console. Команда Inspector `Log Pattern Schedule` показывает все рассчитанные события сразу. **Проверка до закрытия этапа:** в Play Mode сверить сообщения `PatternSchedule planned/reached` с примерами 1–4 раздела 5, переходом между баундами и повторным ID; при одном большом шаге высоты должны выдаваться все пройденные события. Этот этап ещё не создаёт шарики. Проверка в Unity Editor ожидается.
5. **[ ] Рост и переходы.** Код реализован: `ScoreCounter` использует очки как метры высоты и множитель текущего `BoundAsset` вместо множителя старого уровня. При пересечении границы баунда за кадр остаток времени рассчитывается с множителем следующего баунда; расписание событий уже обрабатывает все пройденные пороги. `GameManager.prefab` ссылается на `GameProgression.asset`. **Проверка в Play Mode:** скорость меняется на границах 150 и 1000 м; при текущих настройках множители равны ×1, ×2 и ×4. События не пропускаются при большом шаге высоты.
6. **[ ] Спавн и эффекты.** Код реализован: `BalloonManager` подписан на `PatternEventScheduler` и создаёт шарики по расписанию; старые таймер, случайная позиция и пороги очков удалены. Семь цветов радуги дают по 1 валюты; белый выбирает случайный эффект из Boost/TiltProtection, чёрный — из InputInversion, серый выбирает сторону 50/50 и затем эффект этого типа. Списки эффектов заданы в `BalloonManager.prefab` и не зависят от старых уровней. При пустом списке шарик пропускается с ошибкой. Радиальные координаты берутся из паттерна-источника относительно `spawnAreaCenter`. **Проверка в Play Mode ожидается:** девять событий паттерна появляются в заданном порядке и местах; выбор конкретного эффекта не меняет вид события.
7. **[x] Сохранение и повтор.** Код реализован: `BoundRunController` на `GameManager.prefab` отслеживает высоту и сохраняет максимальный достигнутый индекс баунда в `PlayerPrefs` под отдельным ключом `player_progress_highest_bound`, не смешивая его со старым уровнем. Кнопка Retry и запуск приложения с сохранением запускают быстрый визуальный рост от нуля до `HeightFrom` предыдущего баунда (настройка по умолчанию — 1,5 с). Во время роста физическое управление заблокировано, игровая высота не начисляется, расписание не выдаёт события; перед возобновлением его курсор ставится на первый паттерн баунда повтора, включая события на самой границе. Сброс биты после Retry выполняется при заблокированной физике и синхронизирует позу Rigidbody с Transform. Для первого баунда с высотой старта 0 рост завершается сразу. **Проверено пользователем в Play Mode:** стартовое ожидание на нулевой высоте, визуальный рост после разблокировки ввода и повтор 3-го баунда после достижения бесконечного 4-го.
